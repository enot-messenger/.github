# Участие в разработке

Проект с закрытым исходным кодом: внешние pull request не принимаются. Этот документ описывает процесс для команды.

## Перед началом

1. Прочитайте [`enot-docs/AGENTS.md`](https://github.com/enot-messenger/enot-docs/blob/main/AGENTS.md) — правила и запреты.
2. Прочитайте [`enot-docs/docs/journal.md`](https://github.com/enot-messenger/enot-docs/blob/main/docs/journal.md) — на чём остановились.
3. Требования берите из [`enot-docs/docs/spec.md`](https://github.com/enot-messenger/enot-docs/blob/main/docs/spec.md), а не из памяти.
4. В каждом свежем клоне включите хуки репозитория (один раз):

```bash
git config core.hooksPath .githooks
chmod +x .githooks/pre-push
```

## Ветки и коммиты

- От `main`: `feat/краткое-описание`, `fix/...`, `chore/...`, `docs/...`.
- Conventional Commits: `feat(auth): добавить вход через Yandex`, `fix(voice): не терять поток при смене устройства`.
- Один PR — одна задача. Крупные изменения разбивайте.

## Почему `main` не защищён настройками

Защита ветки и rulesets в приватных репозиториях доступны только на платных тарифах GitHub, а делать репозитории публичными нельзя. Поэтому правило держится на двух механизмах:

1. **Локальный хук** `.githooks/pre-push` блокирует прямой push в `main` до отправки.
2. **Workflow `guard-main`** после каждого пуша в `main` проверяет, связан ли коммит с pull request. Если нет — проверка падает и автоматически создаётся issue.

Запретить пуш технически невозможно — поэтому ответственность на авторе. Обходить хук через `--no-verify` допустимо только при аварийном восстановлении, с записью в журнал.

## Pull request

- Заполните шаблон целиком, приложите ссылку на issue.
- Зелёный CI: линт, типы, тесты, сборка. Обязательные проверки нельзя включить настройками на текущем тарифе — красный CI всё равно считается блокером мерджа.
- Мердж только squash, ветка удаляется. Удобнее всего через CLI:

```bash
gh pr create --fill
gh pr merge --squash --delete-branch
```

- Обновите журнал проекта в этом же PR.

## Обязательные проверки перед PR

- Нет секретов, реальных адресов и настоящих данных — только `example`, `admin`, `user@example.com`, `example.enot.space`, `203.0.113.10`.
- Новые пользовательские строки добавлены в обе локали (ru, en).
- Цвета и отступы взяты из дизайн-токенов, а не захардкожены.
- Лимиты и цены читаются из конфигурации, ключа или БД.
- Для изменений схемы БД есть миграция и описан откат.

## Переменные и секреты

На текущем тарифе организационные переменные и секреты приватным репозиториям недоступны: `DEPLOY_*` и `DEPLOY_SSH_KEY` заводятся в каждом репозитории отдельно. Готовые команды и таблица значений — в [`enot-infra/docs/vps-setup.md`](https://github.com/enot-messenger/enot-infra/blob/main/docs/vps-setup.md).

## Issue

- Баг — шаблон Bug report: что ожидали, что получили, шаги, окружение.
- Задача или идея — шаблон Feature request: зачем это пользователю и как понять, что готово.
- Если функции нет в ТЗ, сначала обсуждение: объём проекта защищён сознательно.
